## Часть 1 — запуск Studio строится из `RunSpec` ядра (P8.B.7)
Мост и сервер перестают собирать `Config`, политику кампании, число ячеек, аренду, бюджет и лимиты своими числами:
источник — `io.astrolabe.RunSpec` (`RunSpec.defaults(profile, stateRoot, mode)` плюс выбор пользователя из
`StartSpec` и настроек). Места — в отчёте B7. Учесть замечания ревью B7: `RunSpec` требует `maxCells`,
`leaseMinutes`, `maxOutputTokens` ≥ 1, а Studio сейчас зажимает (`coerceAtLeast(1)`) — значение 0 из настроек не
должно ронять запуск; режим задачи Studio передаёт сам (умолчание фабрики — `Autonomous`); из Java `copy` требует
все аргументы — сборку делать в мосте на Kotlin. **Тест моста:** запуск Studio с настройками по умолчанию даёт
`RunSpec`, равный `RunSpec.defaults` для того же профиля и режима (настоящая сверка, а не транскрипция чисел).

денежного учёта». Тексты — в оба каталога (`catalog.en.ts`, `catalog.ru.ts`), без слов из `vocabulary.ts`.

## Часть 3 — режим auto и команды класса D (P8.C.15)
Сейчас режим `auto` в Studio молча отклоняет любой эффект класса D, которого нет в allow-list (например, установку
зависимостей вне рабочего каталога или загрузку): модель ищет обходы. Решение оркестратора: в режиме `auto` такой
запрос **показывается человеку карточкой одобрения** (как в режиме `ask`), а не отклоняется; автоматически класс D
не одобряется никогда; allow-list действует как раньше. Место — `HostAuthority.kt` моста и обработка карточек на
сервере; сверить по коду, что именно отвечает `auto` сегодня, и описать в отчёте.
