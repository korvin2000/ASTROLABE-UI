## Зачем
Шлюз P8.W-A (промпт сессии 4A §3 п. 7) требует два живых прогона `real-dirty-repo` на дешёвой модели: в `auto` и в
`ask` с заранее заданными ответами; оба должны дойти до конечного состояния без `agent_error`. Сейчас `eval-live`
знает только политику `auto` (`eval-live/.../StudioAttempt.kt:245-253`: хост сам принимает непроваленные пункты).

## Что сделать
1. Опция `eval-live run --mode auto|ask` (по умолчанию `auto` — прежнее поведение и прежние отпечатки результатов).
2. `ask` ведёт себя как Studio в режиме ask (сверить с мостом `ASTROUI/backend/bridge/.../StudioHost.kt` — только
   читать): `decide` не решает сам, запрос приёмки остаётся ожидающим, кампания останавливается `WaitingForInput`.
   Затем прогон отвечает по сценарию, как пользователь: переоткрывает ту же работу (`work`) в том же корне состояния
   и отдаёт `AcceptanceDecision` с `Decider.Human`, `DecisionKind.Accept` для ожидающего запроса (найденного по
   `AcceptanceDecisionRequest.key`, D-428). Поправки — как сейчас в `auto`. Не больше 3 ответов на попытку; дальше —
   исход `ask-exhausted` в `result.json`.
3. `result.json`: режим, число ответов, итоговое состояние; счётчики `phase.counted` из событий уже пишутся в
   `events.jsonl` — сводку по фазам (git, чтения, объекты, открытия, попытки финала) добавить в `result.json`.
4. Офлайн-тест на поддельном адаптере (как существующие тесты `eval-live`): `ask` доходит до `Completed` после одного
   ответа; `auto` не изменился.
