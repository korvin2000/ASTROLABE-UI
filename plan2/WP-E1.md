## Часть A — оценщики (Codex-W; пакет `io.astrolabe.route`, файл `route/BindingEstimators.kt`, тест `route/BindingEstimatorsTest.kt`)
Чистые функции над записями, без часов и случайности; `explicitApi()`, `data class`, без Kotlin `Result`/`value class`;
обновления — упорядоченные события, чтобы повтор по журналу был детерминирован (§10.4).
1. **Доля кэша по токенам.** Вход: наблюдения `(cacheableTokens b_i, cachedTokens c_i, blockId)`; `n_eff` = число эффективно
   независимых вызовов/блоков **сессии** (не токенов); априор `Beta(1,1)` по умолчанию, настраиваемый. Выход: `q̂ = Σc/Σb`,
   апостериор `Beta(a0 + n_eff·q̂, b0 + n_eff·(1−q̂))`, среднее и 90 % интервал. Исключать перезаписи harness (флаг наблюдения);
   смена апстрима или сессии начинает новую серию (ключ серии — вход); общая доля кэшированного (`Σc/Σвсе входные`) —
   отдельно. Пустой вход → априор.
2. **Задержка.** На сессию `T_i = a_s + b_s·o_i + ε_i` (`o_i` — выходные токены), `v_s = 1/b_s`; коэффициенты неотрицательны;
   устойчивая к выбросам оценка (например, Theil–Sen или Huber; выбор обосновать в KDoc); время инструментов и повторы в
   `T_i` не входят (вход уже очищен); без разброса длины выхода `a` и `v` неразделимы → выход «неразделимо» с общей
   скоростью, а не ложные числа. Инкрементальное состояние (EWMA допустима для `v`, `a` при объявленном `λ`) с явной записью.
3. **Цены.** `C_i = [u_i, c_i, o_i]·p` внутри одного маршрута и яруса (`u` — некэшированный вход, `c` — кэш-чтение, `o` —
   выход; отдельные столбцы для записи в кэш и сборов, если есть). Три независимые строки определяют `p` алгебраически;
   четвёртая и далее проверяют согласие (невязка с порогом); коллинеарность и шум → «недостаточно данных», не оценка.
   Один счёт определяет только свою сумму. Три источника цены хранятся раздельно: `billed` / `documented` / `inferred`
   (`PriceProvenance`).
Тесты: синтетические ряды с известными параметрами (восстановление), пограничные случаи (пусто, одна строка, коллинеарность,
выброс, смена апстрима), детерминизм повторного применения. `./gradlew :core:test --tests 'io.astrolabe.route.BindingEstimatorsTest' -q --console=plain`.

1. **`BindingKey`** (`route/BindingKey.kt`): `model × gateway × upstream? × wireApi`; `upstream == null` → отдельная корзина
   `unknown` (не сливается ни с одной известной). Источники полей: `provider-api` `Request`/`ResponseInfo` (`upstream`
   `Request.kt:144-153`, wire-API профиля), события `cell.model_responded` (A2a). Канонический строковый вид для store и журнала.
2. **Таблица `binding_physics`** в `state.sqlite`, миграция **v7** (`store/Migrations.kt`, идемпотентный раннер; обновить
   таблицу-комментарий в шапке файла): одна строка на ключ: достаточные статистики оценщиков части A (доля кэша: Σb, Σc, n_eff,
   серия; задержка: состояние; цены: billed/documented/inferred с происхождением), рассуждения на запрос (среднее, n),
   ошибки по видам (счётчики), `updatedSeq` (упорядоченность), `schema_version`. Один писатель — учёт (`telemetry/Accounting.kt`
   или новый `route/BindingPhysics.kt`), обновление из `ModelResponded` с согласованным usage; **никакого wall-clock** в строке

3. **Снимок в попытку.** На старте попытки снимок строк физики для профилей попытки замораживается (`AttemptConfig` — поле
   снимка или ссылка на строку `binding_snapshots`), чтобы решения маршрутизации попытки читали снимок, а не живую таблицу
   (ярус «замороженное на попытку», §4.6). Повторное открытие той же попытки читает тот же снимок.
4. **`routing_log`**: каждое решение маршрутизации (`route/Router.kt`, рядом с существующим `CalibrationLog.kt` — изучить и
   переиспользовать, не дублировать) пишет строку: попытка, ячейка/функция, выбранный профиль, `BindingKey`, снимок, причина,
