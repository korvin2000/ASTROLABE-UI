## Цель
Воспроизводимый headless-прогон живого агента на задаче с приёмкой, недоступной агенту на запись: основа baseline (BL),
B2/B4 и D5. Прогон — CLI-процесс из установленного дистрибутива, модель для ожидания не нужна.

## Что сделать
1. Новый модуль `:eval-live` (`io.astrolabe.evallive` или `io.astrolabe.eval.live`), включается в `settings.gradle.kts`
   **только при наличии SDK** — внутри того же `if`, что и `:provider-ai-gate` (D-332). Зависит от `core`,
   `provider-ai-gate`, `eval` (переиспользовать `Arms/Experiment/PairedBound/Scorecard`, где это естественно; не
   дублировать). Плагин `application` → `:eval-live:installDist`; установка в произвольный каталог
   (`-PbenchDir=C:/work.astrolab/bench/<tag>` или копирование `build/install/...`), запуск из него без Gradle.
2. CLI (`eval-live run`): задача(и), модель(и), провайдер (OpenRouter), повторы, каталог результатов, seed порядка.
   На каждый прогон: свежий временный каталог; копия базового репозитория задачи (с `git init` + коммит базы, если
   ядру нужен git); запуск попытки через публичный фасад (`Astrolabe`/`Controller`) с `AiGateAdapter`; после завершения
   — приёмка **из каталога вне рабочей области агента** (скрытые тесты/смоук копируются в отдельный temp только на
   время приёмки; агент их не видит и не может изменить).
3. Конфигурация попытки — как в Studio (чтобы baseline отражал продукт): см. корень
   `ASTROUI/backend/server/src/main/java/io/astrolabe/studio/tasks/TaskService.java` (~541–564: роли, `maxCells` 12,
   лимиты) и `ASTROUI/backend/bridge/.../AutoProfiles.kt` (профили, `OPENROUTER_UPSTREAM_IGNORES`: `z-ai/` → ignore
   `Together`). Studio — не зависимость: воспроизвести минимально и записать в «Решения», что именно скопировано.
4. Результат прогона — JSON на прогон + сводный CSV/JSON: задача, модель, повтор, исход попытки, приёмка pass/fail
   (+ вывод приёмки), время стены, N запросов к модели, токены вход/кэш/выход, деньги — **всё, что уже есть в
   событиях** (A2a добавит счёт, рассуждения, тайминги, апстрим — runner должен подхватывать новые поля без переделки:
   журнал событий `AgentEvent` сохранять целиком в JSONL рядом с результатом). Неизвестное — `null`, не 0.
5. Ключи — стандартным разрешением SDK (окружение / хранилище SDK, как `provider-ai-gate` `LiveSmokeTest`);
   секреты не читать и не печатать; при отсутствии ключа — понятная ошибка с именем ожидаемой переменной.
6. Три задачи v0 в `eval-live/tasks/<id>/` (база, формулировка для агента, скрытая приёмка, эталонный патч):
   (a) bugfix с воспроизводителем; (b) greenfield REST с внешним smoke-скриптом; (c) правка API + вызывающий код.
   Малые (агент — минуты), без сетевых установок (Node 24 без npm-зависимостей / Python 3 stdlib / JDK);
   приёмка каждой задачи проверена: падает на базе, проходит на эталонном патче (тест на это — офлайн).
7. Корневой `.gitignore` правит оркестратор (`bench/`); результаты прогонов в репозиторий не коммитить.
