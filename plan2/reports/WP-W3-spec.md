# WP-W3 — спецификация: одна объявленная политика расходного вывода (после ревью Codex, решения оркестратора)

Ветка `v2/W3`. Опоры: §8.1/§8.4 `docs/verification/scheduler.md`, D-45, D-53 (I-12), D-374, D-427, D-428, №32.

**1. Политика и два правила.** Единственная политика — существующий `ScratchPolicy` (`verify/Scheduler.kt`), второй нет.
Добавлено: `version` (2 = якорные корни; 1 было неякорным правилом и к идентичности не применялось), `id` = SHA-256
кодировки `scratch-policy/v2` (версия, отсортированные корни), `NONE` (версия 0, ничего не исключает), `BUILT_IN`
(`DEFAULT_PREFIXES` как якорные корни). Два правила одного объекта:
- *идентичность* — `excludes(path, tracked)`: путь **неотслеживаемый**, лежит **под корнем, привязанным к корню
  репозитория** (`build/x`, но не `src/build/x`, не `devtools/pkg/tmp/x`), и имя файла не из `EnvFingerprint.LOCK_FILE_NAMES`.
  Вложенный корень — только объявленный явно. Отслеживаемое (индекс) не исключается никогда; `devtools/` не исключается;
- *собственный вывод проверки* — `isScratch` (прежнее совпадение любого сегмента, D-45) убирает свежий вывод из
  перечисленных tested inputs. При политике (версия 2) путь, объявленный известным замыканием, и отслеживаемый путь
  остаются входами при любом имени: закреплены в квитанции, их перезапись — мутация (P1-2, P1-3).
Идентичность = base commit + отслеживаемая дельта (без изменений) + неотслеживаемое неигнорируемое вне `excludes`
(SHA-256 сырых байтов, тип, режим, состав) + env. Исключённое только перечисляется git — не читается, не хешируется, не
канонизируется; нечитаемый вход по-прежнему `UnreadableInput(path)` (WF-4).

**2. Заморозка (P1-5).** Политика замораживается в `AttemptConfig.scratch` при первом открытии — запись попытки
сохраняется **до** захвата s0; повторные открытия читают её же. Попытка, замороженная до W3 (поле отсутствует) = `NONE`:
состав и байты v1, без миграции. Контракт записывает ту же политику (`Contract.scratch`) для авторитета и показа (Studio,
W5); без политики поле не кодируется. Каждый `Stamper`/`DirtyState`/`Scheduler` попытки получает её через `Stamper.scratch`
(`Scheduler` и `DirtyState` берут её у штамповщика; S3: `S3Run`, `Integrator`, `ReplayRebase`). Отчёт штампа:
`StampReport.scratch`, `scratchCount`; снимок: `scratchPolicy`, `scratchCount` (I-12: исключение учтено явно).

**3. Где действует.** Штамп и снимок фильтруют одинаково (`captured == recoverable` сохраняется); перепроверка статуса
git в захвате сравнивает членство под политикой — вывод под корнем во время захвата не исчерпывает попытки (P2-3), а
перепроверка содержимого D-427 не меняется. Через `Stamper.diff` и манифесты — автоматически: сдвиг входов
(`announceMoved`), touched и drift, refresh prescan, финальное сравнение, `DecisionKey`, интеграция S3. Изолированный
кандидат экспортирует каждый отслеживаемый файл при любом имени. `movedPathsHint` называет активные корни.

**4. Кодировки (P2-2).** tracked-delta — без изменений. untracked-manifest: при `NONE` — v1 байт в байт; иначе v2 = строка
`scratch-policy=<id>` + строки v1. Манифест снимка — так же v1/v2. Новые поля JSON (`Snapshot`, `AttemptConfig`,
`Contract`, `Receipt`, `ObligationResult`, `DecisionItem`) помечены `@EncodeDefault(NEVER)`: записи без политики
сохраняют свои байты и отпечатки. Версия политики отделена от версии кодировки. `CaptureBytesTest`: векторы v1 не
тронуты, добавлены v2 (деревья снимков и tracked-delta совпадают с v1 — вывод `out/` в них не попал).

**5. Квитанции (P1-2, P2-1).** `Receipt.inputPolicy` = id политики, под которой сняты штампы, tested inputs и манифест;
квитанция под другой политикой — `stale` до любых коротких путей (равенство штампов, доказательство переиспользования).
Закреплённый вход вне идентичности (неотслеживаемый под корнем, объявленный замыканием) перечитывается с диска при
оценке актуальности (D-374); изменился — квитанция негодна («inputs outside the candidate moved since the check»).

**6. Вход, переписанный проверкой (WD-14, c15, P1-3, P1-4).** Остаётся входом; квитанция негодна. `Currency`,
`ObligationResult` и `DecisionItem` несут типизированный `rewrittenInputs`; запрос решения называет пути. Без новой
информации повторный вход отдаёт тот же запрос (W1). «Принять как есть» — существующий `Accept`: запись решения,
`accepted`, никогда `verified`. Фактический красный результат с переписанным входом остаётся **красным**
(`Obligations.run`, `fullSuite`): мутация не превращает его в пробел, который покрывает решение.

**7. Хвосты W2.** *Атлас:* `Atlas.build(root, captured)` берёт hash8 файлов, которые атлас не разбирает
(`Language.Other`), из **этого** открытия (`DirtyState.latest`: s0 или drift-захват переоткрытия; при совпадении размера),
и читает только разбираемые; строки те же, outline — по запросу; в идентичность атлас не входит (P3). *Переоткрытие
перечитывает дерево:* хвост (нужен межпроцессный кэш, т.е. доверие метаданным для базы drift — решение владельца).

**8. `Controller.kt` (W4, правлю только после слияния W4):** `Stamper` создаётся после `frozen` со
`scratch = frozen.scratch`; `deriveS0(..., scratch = frozen.scratch)`; `Atlas.build(workspace.root, dirty.latest…)`;
`fullSuite`: красный = `c.red && Current && (c.eligible || c.rewrittenInputs.isNotEmpty())`, `NotCertified` несёт
`rewrittenInputs` в результат `FULL_SUITE`; `ask` строит пункты через `Resolved.decisionItems`.

## Ревью Codex → решения
| Замечание | Решение |
|---|---|
| P1-1 любой сегмент прячет исходники | исправлено: `excludes` — только якорные корни, отслеживаемое и lock-файлы первичны (§1); вложенный корень — только объявленный |
| P1-2 исключение из идентичности ≠ из входов | исправлено: «не читать» — только захват идентичности; объявленный путь закреплён в квитанции и перечитывается (§1, §5); неизвестное замыкание — как игнорируемые файлы сегодня (§8.4), принятое ограничение |
| P1-3 «объявить выводом» не сходится | выбор (b) отложен в сессию 4B (W6/W7, протокол поправок) — хвост; в W3 вход остаётся в обнаружении мутаций, «принять как есть» = `accepted` (§6) |
| P1-4 красный + мутация → пробел | исправлено: красный остаётся красным (§6); негативный сценарий |
| P1-5 политика не заморожена | исправлено: `AttemptConfig.scratch` до s0, наследие = `NONE`; запасной путь «встроенная по умолчанию» снят (§2) |
| P2-1 старые квитанции | исправлено: `Receipt.inputPolicy`, проверка до коротких путей (§5) |
| P2-2 байты v1 | исправлено: `@EncodeDefault(NEVER)`, векторы v1 не тронуты (§4) |
| P2-3 сырой статус в перепроверке | исправлено: членство под политикой (§3) |
| P2-4 ошибки обхода, подрезка | обход не подрезается (фильтр после перечисления); fail-closed на ошибке обхода и большие входы — хвост |
| P3 атлас и исторический s0 | исправлено: дайджесты только этого открытия (§7) |

**Хвосты.** Выбор «объявить выводом этой задачи» (4B); fail-closed при ошибке `filesUnder` и большие входы; мемоизация
`WorkspacePath.canonicalise` (≈ 60 % времени ячейки на 1500 файлах, отдельная измеряемая правка, D-47); переоткрытие
перечитывает дерево; `git status -uall` по-прежнему перечисляет расходные файлы.
