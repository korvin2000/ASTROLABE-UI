## Решения
(черновые, без номеров: вопрос → выбор → почему → безопасная альтернатива)

1. **Сколько семейств и как назвать операцию заметок.** → 6 семейств / 22 операции; заметка — `state.note`, семейство
   `state` остаётся (подтверждено B8). Почему: `ToolFamily` — публичный enum, по нему работают диспетчер,
   `CellTools.state`, права и `requiredOp` loop-гейта. Альтернатива: скрыть `verify` целиком.
2. **Словарь операций.** → два словаря: структурные списки `ToolOps.*` не меняются (маски, схемы — байты `[S]`);
   «известные операции» = структурные + `ToolOps.directOnly`; все проверки «это вообще операция?» читают второй.
   Альтернатива: добавить в общие списки и вычитать в каждом потребителе масок/схем (больше мест, выше риск байтов).
3. **`recall` → `read(id)`.** → не объединять: `look.recall` остаётся (указатели «recall #N» в ≥ 10 местах общего
   слоя). Альтернатива: синоним `look(read, id=#n)`.
4. **`poll`.** → скрыт; формулировка `Run.kt:741` делается нейтральной для обоих протоколов.
5. **Поля `note`.** → `note{kind, text, evidence?, closes?, refutes?}`; недостающие поля записей регистра заполняет
   harness (`because = ""`, `scope = "task"`, `reopen = "new evidence"`, `reason = "stated in the change"`).
6. **`hypothesis` со свидетельством = проверенный факт**; якорь — из свидетельства, если это наблюдение одного файла.
   Альтернатива: без якорей (заметки не устаревают).
7. **`refutes` атомарно.** → D2 проверяет цель и свидетельство до построения патча из двух операций; иначе отказ
   всей заметки (валидатор сам пропустил бы опровержение и записал тупик — D-373).
8. **Чтение заметок.** → зарезервированный `id="notes"` у существующей `look.recall` (без новой операции — 22
   остаются), плюс id в строке `[A]` и полный активный регистр в переносе. Альтернатива: отдельная операция
   `state.notes` (23 операции).
9. **Архив регистра.** → порядок: закрытые open → опровергнутые факты → решённые поправки; номера не
   переиспользуются (счётчик по активным ∪ архивным). Архивация — не прогресс и не сбрасывает подписи loop-гейта.
   Заметка, не помещающаяся после архивации, отклоняется с подсказкой `closes` / `refutes`, ячейка продолжается;
   блокер ёмкости — только когда заметку требует loop-гейт (принято оркестратором по возражению 1).
10. **Счётчик финализаций.** → считает только обычные отказы; сброс, если после прошлого счётного отказа сменился
    штамп дерева или в реестре проверок появилась новая последняя квитанция (сравнение до verify-on-stop самой
    заявки); предел 2. Альтернатива (Codex): счётчик только диагностический.
11. **Классификация `finish`** — по именам испущенных вызовов `edit`/`run`/`verify` до разбора аргументов;
    невыполненное условие → «finish not attempted», никогда не считаемая заявка.
12. **Типизированные факты.** → `ToolOutcome.ready`, `Handle.ready`; «проходит» = `green` или `ready`.
13. **Результат `task(finish)`** — постоянная строка; вне loop-гейта; не terminal-вызов; разрешён на резервном ходу.
14. **Grant handoff.** → журнальные записи `handoff-grant` (лимит) и `handoff` (расход, до диспетчеризации, не более
    одной на переданную ячейку); новый grant — только при явном resume завершённой кампании (`Controller.kt:537-539`,
    D3 журналирует его там); лимит grant фиксируется при создании.
15. **Запись `returned_handoff`** — по образцу `returned_completion` (артефакт до строки); хранит то, что нужно
    переносу, маршрутизации и итоговому отчёту.
16. **Handoff по бюджету ходов** — только S0, только если с начала эпохи записана новая проходящая квитанция,
    текущая для дерева (смена штампа сама по себе не прогресс — принято оркестратором по возражению 2); в S1
    остаётся прежнее продолжение в счёт `maxCells`.
17. **Носитель переключателя** — `Role.protocol` + `Config.protocol`; S2/S3 при `Direct` идут структурно.
18. **Версии в заголовке `[S]`** — `roles/5`, `error-policy/5` не меняются; 13 строк error policy для direct.
19. **Gauge** — без переключателя (`STATE vN` = версия заметок).
20. **Журнал `[A]`** — порядок и пределы; 800 — порог сокращений, жёсткий предел 5000; строка id вне предела Notes.
21. **`requiredOp` loop-гейта** остаётся `"state"`; меняется только текст.
22. **Seeds** — direct всегда `SeedRule.V2`; структурный — `Defaults.seedRule`.
23. **Событие** — `AgentEvent.Cell.Ended.partialReason: String? = null` (snake_case причины) для обоих протоколов.

## Отклонения от карточки и плана
План расходится с кодом — в спецификации выбран реализуемый вариант (прав код):
1. **Число операций.** План: 7 семейств / 37 → 5 / ≈ 19. Код: 38 (A5 добавил `run.wait`). Спецификация: 6 / 22.
2. **`recall` → `read(id)`** — не реализуется (решение 3).
3. **`run(wait: exit | line:<re> | port:<n>, deadline)`** — в коде операция `run.wait` с `until_line`, `until_port`,
   `timeout`; взяты имена кода.
4. **«Переключатель protocol в трёх местах».** В коде ~45 мест (таблица A-D.7): 1 правило валидатора + инертные,
   ~10 текстов, рендер `[A]` и переноса, `[S]`, два словаря операций (7 проверок), завершение, handoff, 12 мест
   выбора роли.
5. **§1 №18, `Rebuild.kt:132`** — это текст `[A]` перестроенной проекции, а не seeds; seeds перестройки выбирает
   `Cell.kt:1099-1104` тем же `CarryForward.carry`.
6. **«Дайджест ≤ 150».** Код: 150 + 8 на требование, потолок 2000 (D-270). 800 токенов — цель.
7. **«Touched 3».** В структурном якоре 10, до 3 — только под давлением. Для direct — всегда 3.
8. **`finish`.** В коде операции нет: заявка — ход без вызовов (`Cell.kt:581`). По решению B1 в direct первый пустой
   ход — подсказка, заявкой становится второй подряд.
9. **«Сожжёт три попытки за шесть ходов».** `maxFinalizations = 2` (`ExitGate.kt:88`).
10. **`PartialReason.Handoff` → `Disposition.Continue`.** В S0 `Continue` сейчас = остановка (`Controller.kt:1410-1411`,
    D-64); пакет не-завершённой ячейки не хранится — нужны ветка продолжения и kept-запись.

## Возражения исполнителя
1. **B12, блокер ёмкости регистра — принято оркестратором, внесено в спецификацию.** Было: не помещается после
