# WP-W0 — сценарный каркас, фикстура «грязный репозиторий», счётчики фаз, реестр инвариантов

Ветка `v2/W0` (от `main` `de71221`). Исполнитель: суб-агент t3 (Opus).

## Сделано
- **Счётчики фаз** (п. 3): `Git` считает запущенные процессы (`processesStarted`, в `exec`) и объекты `hash-object -w`
  (`objectsWritten`); `Workspace.bytes` — прочитанные файлы и байты (`filesRead`, `bytesRead`); всё `internal`,
  монотонно на экземпляр. Новое событие `phase.counted` (`AgentEvent.Telemetry.PhaseCounted`: `counted`,
  `gitProcesses`, `filesRead`, `bytesRead`, `objectsWritten`, `opens`, `finishAttempts`) и словарь
  `telemetry/CountedPhase` (`open`, `snapshot`, `finish`); разности снимает `telemetry/PhaseMark`. `Controller`
  выпускает событие в конце каждого `open` (вся открывающая фаза, включая git-команды хранилища на свежем `Git`),
  в каждом `snapshot(tree)` (граница/контрольная точка хода, захват + снимок) и на каждую попытку финала
  (`stopOrFinish` после проверки «всё проверено»; тело вынесено в `finalAttempt`, поведение не менялось).
  Счётчик открытий — на экземпляр `Controller`, попыток финала — на `OpenedCampaign`.
- **Каркас** `io.astrolabe.workflow.Scenario` (тесты ядра): реальная композиция `Controller.open` → `run` → ячейка →
  диспетчер → инструменты с `FakeAdapter`; один `FakeClock`, один `FixedIdGen`, один `Events` + `EventRecorder`.
- **Фикстура** `DirtyRepo`: один коммит (`src/app.py`, `src/util.py`, `tests/test_app.py`, `data/notes.json`,
  записанный вывод pytest), нет `.gitignore`, `devtools/` из N−1 мелких файлов + `devtools/build.lock` +
  `devtools/bundle.bin` 20 МБ; варианты `ScratchOutput` (пишет `build/report.txt`), `RewritesData`
  (переписывает `data/notes.json`), `LockedFile` (Windows — исключительная блокировка `FileChannel.lock()`, Linux —
  права `---------`, иначе `Lock.Unsupported` с причиной и пропуск). Генерация < 1 с.
- **Сценарий** `DirtyRepoScenarioTest`: открыть → правка/verify/done → `Completed` → переоткрыть; события содержат
  ненулевые счётчики всех трёх фаз. `DirtyRepoTest` проверяет форму фикстуры и все три варианта.
- **Реестр** `docs/reference/workflow-invariants.md`: правила §7.2 (правило защиты — п. 4 в шапке), WF-1…WF-15 —
  все `pending P8.W.<n>`, файлы по WD, счётчик.
- **Живая задача** `eval-live/tasks/real-dirty-repo` (баланс считает возвраты дважды): `task.json` с новым полем
  `dirt` (`DirtSpec`: каталог, число файлов, МБ большого файла), бенч кладёт грязь после коммита базы
  (`Bench.runOne`); база без `.gitignore`, видимые тесты пишут `build/test-report.txt`. Отпечаток задачи (`Arms.task`)
  включает `dirt` только у грязных задач — отпечатки прочих задач не изменились. Офлайн-тест `DirtyTaskTest`.
- **COMMON.md**: раздел «Инварианты рабочего процесса (§7.2, решение №36)».

## Решения
- Где считать «файлы за захват» → в `Workspace.bytes` (единственная точка чтения дерева, D-47), разностью за фазу →
  без правок захвата. Альтернатива — счётчики внутри `DirtyState.capture` (точнее, но шире правка).
- Куда класть счётчики → новое событие, а не поля существующих событий: у снимка и финала своих событий нет.
  Исчерпывающих `when` по `AgentEvent` в модулях нет — добавление безопасно.
- Открытие: база git-счётчика 0 для `open(repo, …)` (свежий `Git`, считаются и команды `Store.open`), текущее значение —
  для `open(project, …)`.
- Сценарий 1500 файлов — только при `ASTROLABE_WF_1500=1` (см. отклонения); зелёный сценарий в наборе — 300 файлов.
- В приёмке живой задачи нет проверки `devtools/`: валидация (`TaskValidityTest`) строит копии без грязи.

## Хвосты и риски
- Счётчики — разности на экземпляре `Git`/`Workspace`: параллельная работа на том же дереве в ту же фазу
  (S3-писатели на своих деревьях не мешают) попадает в фазу. Чтения `BlobStore` (WD-02 `put`/`get`) не считаются —
  это хранилище, не дерево; W2 может добавить.
- `opens` — на экземпляр `Controller`; WF-1 (W5) считает события `open` на действие хоста в Studio.
- Событие `snapshot` выпускается и на каждой контрольной точке хода (`TurnCheckpoint`) — больше событий в потоке.
- Живая задача: `GitRepo.changedFiles` перечислит 1500 файлов `devtools/` как изменённые — это и есть наблюдаемое
  поведение, но сводка результата будет шумной. Живой прогон в линии не запускался.
- Studio не трогал; WF-1/8/10/11 потребуют `*WorkflowScenario*` в Studio.
