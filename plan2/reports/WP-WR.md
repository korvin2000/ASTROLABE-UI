## Решения
- **Что входит в ключ** → текущие байты закреплённых внешних путей, а не пины квитанций. Почему: пин не меняется,
  когда меняется файл (квитанция та же), а ключ должен меняться. Сравнение для повторного использования — «на момент
  вопроса» против «сейчас»: вопрос, заданный уже при недействительном свидетельстве, остаётся тем же вопросом, пока байты
  снова не изменятся. Альтернатива — непрозрачный дайджест-строка вместо карты (компактнее, но не называет пути).
- **Повышение версии ключа для всех запросов** (v3 и при пустой карте) → по карточке; сохранённые в Studio решения со
  старыми ключами не найдутся — пользователя спросят снова (безопасная сторона). Studio правка не нужна:
  `HostAuthority.kt:28` шлёт `request.key`.
- **P1-2 только для `accept`** → `rework` ничего не покрывает и ведёт к переделке; менять его не требовалось.
- **P1-3 только для объявленных замыканий** → у неизвестного замыкания перечисленные входы включают игнорируемые файлы
  (`.venv/` и т. п.); их экспорт менял бы стоимость и поведение вне находки.
- **P1-4: решение по происхождению** → в сценарии с двумя решениями AC-1 принят первым (R1), а последнее решение шлюза
  (R2) его не называет (перенесённый пункт отфильтрован); переприёмка с решением R2 не держалась.
