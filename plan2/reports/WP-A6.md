## Решения
1. **`cd` в строке `cmd`** (найдено при 1a). Вопрос: `cd ci && rm -rf workflows` проверял `workflows` от корня, а
   удалялся защищённый `ci/workflows` (W вместо D). Выбор: после `cd`/`chdir`/`pushd` каждый следующий сегмент
   классифицируется во **всех** каталогах, где он может выполниться (старый — на случай `||`, `|`, подоболочки), берётся
   максимум; нечитаемый `cd` (`$DIR`, `~`, `-`, без аргумента в `sh`) делает последующие относительные пути
   неразрешимыми → D. Почему: строже при сомнении, дёшево. Безопасная альтернатива — любой сегмент после `cd` с путём
   удаления/записи считать D.
2. **`$null` и `NUL:` как цель перенаправления** → D на обеих платформах. Вопрос: `literal()` (D-375) считает `$` и `:`
   нелитеральными везде; для `cmd.exe` `> $null` создаёт файл `$null` (раньше тест ожидал W). Выбор: общий строгий
   `literal()` без платформенных исключений — привычка PowerShell в строке `cmd` двусмысленна; отказ подскажет `2>nul`.
   Альтернатива (мягче): на Windows считать `$` литералом только для целей перенаправления → W.
3. **`rmdir` наравне с `rm`/`rd`** (карточка: «только `rm`/`rd`»). `rmdir /s` — тот же встроенный `cmd.exe`, что и
   `rd /s`; POSIX `rmdir` удаляет только пустые каталоги, поэтому ссылки внутри не трогает. Живой вызов D-373 —
   `rmdir /s /q .tools`. Альтернатива — исключить `rmdir` (тогда `rmdir /s /q node_modules` останется D).
4. **Цель внутренней ссылки** (п. 2): «внутри рабочей области и не под защищённым путём», а не «внутри удаляемого
   поддерева» — monorepo-ссылки `node_modules/@scope/lib → ../../packages/lib` должны проходить; `rm -r`/`rd /s` по
   ссылкам не ходят, проверка цели — запас. Висячая ссылка → `toRealPath` падает → D.
5. **Процесс-подстановка `>(cmd)`** как цель записи → D (не литеральный путь): скрытая команда; раньше была W/unknown.
6. **Тело heredoc** после разбиения по строкам классифицируется как команды (строже; раньше вся строка была одним
   сегментом, и абсолютные пути тела всё равно давали D).
7. **Pending-save crash (п. 4)** — без кода. Окно: `Transition.Returned` зафиксирован, `verify` и `Acceptances.save`
   (D-339) ещё нет (`campaign/Controller.kt` ~1362–1477). При возобновлении `resumePending` ничего не находит, приращение
   остаётся `InProgress`, ячейка — `Completed`; цикл выбирает его снова и запускает ячейку-продолжение, которая видит
   дерево с правками прошлой ячейки и предлагает заново; её предложение проходит обычную проверку и решение.
   Неверного состояния нет: коммит и решение возможны только после сохранённого pending; `Returned` пишет лишь статус и
   размер ячейки. Цена — модельные вызовы одной ячейки и повтор проверок. Идемпотентность потребовала бы
   персистировать `CellExit.Completed` (пакет, регистр, текст, флаги целостности тестов) до `Returned` и при открытии
   пере-проверять его без модели — это `Controller.kt` (горячий файл A1) и схема хранилища; не делалось. Безопасная
   альтернатива — та же: продолжение ячейкой.
8. **Зонд запуска в `ProcOwnershipTest`** (п. 6). CI-лог попытки 1 запуска 36026485370 (2026-09-24, windows-latest):
   `pattern READY never appeared in the log of pid 5948 after 120194ms, status Running; saw:` — `powershell.exe` висел
   без вывода все 120 с, т. е. зависший процесс, а не долгий старт. Выбор: ожидание 60 с; молчащий зонд завершается и
   измеряется новый с прежним полным ожиданием 120 с; считается только ответивший. Утверждение теста (дедлайн убивает
   внука) не ослаблено — меняется только измерение. Альтернатива — одно ожидание 180 с (не лечит зависание).
9. **`version` 64-hex в якоре факта (п. 8)** — тип не меняется. `Anchor.version: FileVersion` — полный SHA-256 сырых
   байтов (D-47, I-05): по нему сравнивается устаревание (`Register.kt:133`), он хранится в журнале регистра. Модель
   64 hex не набирает: D-365 (`PatchParser.anchored`) принимает ≥ 4 hex и разрешает по показанным версиям пути, рендер
   — `hash8`. Укорачивание типа дало бы коллизии и миграцию сохранённого регистра без выгоды. В direct-протоколе якорь
   не нужен (план §5).

## Хвосты и риски
- TOCTOU между сегментами одной строки закрыт (ревью п. 2); остаётся окно между пробой и запуском одного сегмента
  (внешний процесс меняет диск) — общая особенность D-375.
- Ссылки в цепочке предков пути записи проверяются только для целей перенаправления; аргументы `cp`/`sed -i`/сборщиков
  по-прежнему лексические (общая граница W-класса; пост-фактум — diff штампа только внутри рабочей области).
- Лимит обхода `DiskContainment` 20 000 записей: большой `node_modules` остаётся D по лимиту.
- Поведение для модели стало строже в нескольких местах (D вместо W): `> $null`/`2>$null` в строке `cmd`, удаление
  под tmp без пробы (в `run` проба есть всегда), строки после нечитаемого `cd`, `>(…)`; после ревью — любой
  delete/move/redirect после сегмента с неизвестными эффектами (`npm run build && npm test > test.log`), `cd..` в cmd.
