## Ревью Codex (через оркестратора: «слить с исправлениями») — что исправлено
1. **bug, цены пула**: связка без собственных цен больше не наследует пул как «Billed». `PriceSource` = `Fitted`
   (своя связка) / `Pooled` (пул апстримов, оценка) / `Catalog` (документировано, оценка); у `CallPrices` —
   `agreement` и `estimate`; собственная подгонка связки остаётся `Unidentified` в таблице цен. Оплаченное
   (`ModelCall.billed`), документированное (каталог) и выведенное (подгонки) раздельны. Тест: связка B с одним
   вызовом → `Unidentified`, её вызов оценён пулом с `estimate = true`.
2. **bug, неизвестная запись в кэш**: `CallUsage` различает «неизвестно» (`null`: класс в `unknown` провайдера) и
   «нет класса» (0 + `absent`); `input`, строки подгонки и цена больше не подставляют 0 вместо неизвестного;
   сверка анатомии включает все категории — неизвестная даёт `unexplained = null` и `complete = false`; неполнота
   идёт в итоги прогона и группы (`partial`). Тест на `cache_write_5m` в `unknown`.
3. **bug, восстанавливаемость в «что-если»**: вместо агрегата на ход — резидент на каждый результат: указатель
   восстановления только у результата с алиасом и не у ещё работающей команды (в ядре указатель есть, лишь когда
   алиас разрешается в наблюдение; правило воспроизводит потери журнала на первых двух батчах `W-letk4` и 22 против
   23 в сумме; без учёта `running` было бы 10); класс — по инструменту и операции; размер — равная доля `R_t`
   (строка без алиаса — не больше 40 токенов). Ошибочные результаты журнала (схемные ошибки, «not executed»)
   входят в `[T]` без указателя. Немедленная заглушка воспроизводится на живых восстанавливаемых результатах,
   читавших выброшенный путь. Новый тест доходит до `R_max`: по бюджету вытесняется только восстанавливаемое
   (потерь 0), по возрасту невосстанавливаемое — потери.
4. **bug, кап кэша**: каждая оценка кэшированного (наблюдённая, сдвинутая на отклонение провайдера, полный
   префикс) ограничивается префиксом до первого элемента, который переписал сценарий (`kept`).
5. **bug, запись в кэш дважды / бесплатные классы**: вход делится один раз (`all = content + A`, запись уже внутри),
   отсутствующая цена класса с токенами не превращается в 0 — «что-если» тогда `unmeasured` («unpriced calls…»).
6. **risk, МНК**: `PriceFit` сообщает `condition` (κ матрицы плана с нормированными столбцами, Якоби),
   `sensitivityPerMillion` (наибольший сдвиг цены при сдвиге каждого счёта на единицу последнего знака,
   `Σ|((XᵀX)⁻¹Xᵀ)_ji|·10^−s_i`) и `standardErrorPerMillion` (`σ̂·√((XᵀX)⁻¹_jj)`, при `n > d`); отрицательная цена →
   `Agreement.Negative`, цены не заявляются (тест). Находка Relace подтверждена (κ = 2,13).
7. **risk, «границы»**: поля `low/high` убраны; стоимость сценария — «условная оценка на этом журнале при фиксированной
   траектории», `calibrationError` — отдельно; вывод об оптимуме k снят (см. «Отклонения» п. 2).
8. **nit**: в `audit.md` — `q̂ = Σ min(c, b) / Σ b`; Beta-апостериор `q` явно отнесён к E1 (KDoc `AuditMath.qHat`).

## Решения (черновые, без номеров)
1. **Определение «доли попаданий» F §6.1 (86,7 %)** → `Σ cache_read / Σ input` по токенам по всем вызовам прогона
   (`input = uncached + cache_read + cache_write`) — на `live1/W-letk4` ровно 0,8670. Кандидаты: доля вызовов с
   `cache_read > 0` — 97,0 % (98,5 % без первого); `Σc / Σ min(I, I₋₁)` — 90,2 %; `Σc / Σ(I − A)` — 89,0 %;
   `q̂` по неизменному префиксу — 99,6 %; пул live1 — 87,3 %. Воспроизводит только токенная доля. Записано в KDoc
   `CacheReport` и `AuditMath.hitShare`. Альтернатива: показывать рядом `q̂` (делается).
2. **Счёт старых журналов** (до A2a): `usage.native.cost` OpenRouter — то же поле, что A2a кладёт в `usage.billed`;
   читается только при `provider == openrouter`; апстрим — из `native.cost_details.upstream_inference_cost`.
   Альтернатива — считать счёт неизвестным (тогда F не воспроизводится).
3. **МНК цен — точный**: нормальные уравнения в целых (счета × 10^s), Крамер с детерминантами Бэрейса, округление
   только итогового частного (DECIMAL128); класс без токенов — без цены; вырожденная система или отрицательная цена —
   цен нет. «Точно» — каждый счёт воспроизведён с точностью 10⁻⁶ от себя; `n = d` — «определено без проверки».
4. **Источники цен**: своя связка → пул апстримов (оценка) → каталог (оценка) → нет; пул используется только для
   связки, чьи вызовы не определяют цен.
5. **«Неизвестно» против «нет класса»**: класс в `BillableUsage.unknown` → `null` и неполнота итогов; класс, которого
   нет ни в количествах, ни в неизвестных (у OpenRouter — запись в кэш), → 0, в таблице `n/a`.
6. **База денег прогона**: счёт, если оплачен каждый вызов с usage, иначе оценка; доли — от базы; расхождение цен со
   счётом — отдельной строкой («не объяснено»).
7. **Шаг кэша (§10.4)**: `b = max(0, min(I₋ − A₋, I − A))`, `s = max(0, b − c)`; разрыв — `s > max(2048, 0,1·b)`;
   полный промах — `c ≤ 0,05·b`; `q̂ = Σ min(c,b) / Σ b` по шагам без перезаписи harness и без смены апстрима;
   группы — `Σmin(c,b)/Σb`.
8. **Причины разрыва (приоритет)**: полный промах после гейта `reserve` → W4; батч вытеснения (журнал; на шине —
   каденция `k` при `t ≥ 2k`, `t mod k = 0`) → W3; сброс Workset → W7; смена апстрима → `Upstream`; иначе — провайдер.
9. **W1** — расход после первого зелёного результата проверки после первого изменения рабочего дерева, не сменённого
   красным до конца (проверка: вердикт `verify`; тестовый вердикт `run`; в журнале Studio — команда `run`, бывшая и
   красной, и зелёной). В детали — что было после (§9.1). **W2** — полная стоимость вызовов с `run(op=poll)`.
   **W3/W4/W7** — `s·(p_u − p_c)` по разрывам своей причины (брутто). **W5** — перенос тел `edit/create` по
   следующим запросам ячейки + повторная генерация тела пути; на шине — `null`. **W6** — `Σ A·p_u`.
10. **Восстанавливаемость результата в «что-если»**: указатель — у результата с алиасом, кроме ещё работающей команды
    (`status=running`); размеры результатов в журнале не записаны — доля `R_t` поровну (строки без алиаса ≤ 40).
11. **Происхождение**: accept-unverified = приёмку дало решение `acceptance` (запрашивается только при непроверенных
    обязательствах, D-339); правки тестов — эвристика путей; группа — имя входного каталога × `provider/model`.

## Отклонения от карточки
1. **W1 на `live1/W-letk4` = 33,7 % против 31 % у F**: F начинает хвост с вызова 42 (установка Playwright), аудитор —
   после зелёного smoke на ходу 39, т.е. включает вызовы 40–41. Определение механическое и записано (решение 9).
2. **«Что-если» и оптимум k**: на этом журнале при фиксированной траектории условная оценка k = 17 на 13,2 % выше
   повтора k = 8 (выкл. — на 81 %): без каденции срабатывает граница `R_max` (батчи по бюджету с хода 30), а перенос
   живых результатов стоит больше сэкономленных промахов. Ошибка калибровки +0,97 %. **Вывод об оптимуме k не
   делается** (ревью Codex): размеры результатов в журнале не записаны, повтор — не точный; аналитика F/Codex («k ≈ 17»)
   не учитывала `R_max`.
3. Карточка: «`EventRecord` JSONL». Читается JSON-деревом, а не `EventRecord.serializer()`: формат Studio — не
   `EventRecord`, а старые журналы содержат события/поля, которые текущая типизация может не принять; ядро только
   читается (`Residency`, `Defaults`, `HeuristicEstimator`, `Item`).
4. Дополнения сверх карточки: причина разрыва `Upstream` (§10.4); вывод вытеснений на шине по каденции; сверка
   повтора со счётчиками батчей журнала; CLI принимает несколько входов и `--catalog`.
5. Объём: ≈ 1,9 тыс. строк main (с KDoc) + 0,7 тыс. тестов против оценки 1,2 тыс. ± 40 % — из-за «что-если», рендера
   Markdown и правок ревью.
