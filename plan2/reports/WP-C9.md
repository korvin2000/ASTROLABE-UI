# WP-C9 — `run(op=poll)`: срезы редактируются через границы опросов (P8.C.9, хвост D-387)

Ветка `v2/C9` от `main` (`97ce447`), запушена.

## Сделано
- `core/src/main/kotlin/io/astrolabe/auth/Redaction.kt`: `applyLive(bytes, content, openAtEnd, context = "")` (internal) —
  новый параметр `context`: текст потока перед окном сканируется вместе с окном (все шаблоны + `liveBlocks`), но не
  выводится; находки обрезаются по смещениям окна. Блок, открытый в контексте, скрывает часть окна до своего `END`
  (или всё окно, если `END` нет); то же для многострочных шаблонов хоста. Маска и `hits` — в номерах строк окна.
  Публичный `apply`/`applyBytes` не изменён (в `redact` передаётся `context = ""`).
- `core/src/main/kotlin/io/astrolabe/tool/run/Run.kt`:
  - `poll`: срез редактируется `applyLive(newBytes, ModelFacing, openAtEnd = before == null, context = before)`, где
    `before = logBefore(proc, since)` — до `maxBytes` лога перед курсором; нечитаемый префикс → безопасная сторона
    (`openAtEnd = true`, окно без маркеров скрыто целиком).
  - `logBefore` выделен из `insideKeyBlock` (чтение префикса лога, которым `wait` определяет старт внутри блока);
    `insideKeyBlock` теперь его вызывает, семантика `wait` не изменилась.
  - Первый срез фонового запуска (`Launch.Background.firstOutput`: вид и blob `LOG`) редактируется `applyLive`
    вместо `applyBytes`, чтобы блок, открытый в первом выводе, был скрыт с `BEGIN` до конца среза.
- Доработка оркестратора (коммит `aab7fb1`): утечка «`BEGIN` + тело без `END` в терминальном виде» закрыта без
  изменения публичного `apply`:
  - blob `LOG` любого запуска (foreground и bg) — `applyLive(…, openAtEnd = false)`;
  - foreground `finish`: маска захвата — `applyLive(output, ReusableEvidence, false)`, вид — `safeView(shaped.view, output)`;
  - `ended` (терминальный `poll` и `wait`) читает лог с байта 0, поэтому контекст пуст (`logBefore(proc, 0)` = "");
    `safeLog = applyLive(log, …, openAtEnd = !fromStart)`, вид — `safeView(shaped.view, log, unknownEnd = !fromStart)`.
    Если лог пропал и остался только последний срез, блок считается открытым (безопасная сторона);
  - `safeView`: шейпер читает сырой захват, поэтому его вид редактируется через `applyLive` как конец живого потока.
    `openAtEnd` ставится, если последние `maxBytes` захвата оставляют блок открытым (`leavesKeyBlockOpen`, общий с
    `insideKeyBlock`). Вид, который начинается внутри блока (`END` без `BEGIN`), скрывается до `END`;
  - `look.read` (файлы) и путь MCP не тронуты.

## Решения
- Где хранить состояние сканера «на handle» → **выводится из собственного лога handle** (префикс `maxBytes` перед
  `since`), а не сохраняется в `Handle` → поле в `Handle` меняет публичный API и тело в `handles` (вне разрешённых
  файлов), а in-memory кэш теряется при рестарте/reattach и не работает для произвольного `since`; лог — канонический
  источник, тот же, что использует `wait` (`insideKeyBlock`), поэтому работает после рестарта и с любым `since`.
  Безопасная альтернатива при необходимости длинных блоков: персистить флаг «блок открыт на курсоре» в `Handle` (схема).
- Как не заводить второй разбор → один механизм `applyLive` (тот же, что у хвоста `wait`), расширенный контекстом;
  без отдельного сканера в `poll`. `ReadinessScan` не тронут.
- Контекст сверх лимита сканирования → окно по-прежнему обрезается по `maxBytes`, контекст (≤ `maxBytes`) сканируется
  дополнительно: до 2×`maxBytes` на опрос → цена приемлема, лимит вывода не меняется.
- Нечитаемый префикс при успешном `os.poll` → скрыть (openAtEnd) → безопасная сторона; альтернатива — прежний разбор
  среза в одиночку с ограничением в маске.
- Первый срез `bg`-запуска → тоже live: это первый срез того же потока; изменение — две строки в `run()`.

## Ревью Fable (исправлено в `8848ee0`)
1. **MCP** (`run(mcp:…)`): blob — `applyLive(…, openAtEnd = false)`; шейпер читает отредактированный ответ, вид — через
   `safeView`; в `render` теперь передаётся `captureMask = safe.mask` (раньше было `NONE`). Тест — `MountTest`: ответ с
   `BEGIN` и телом без `END` не виден ни в виде, ни в blob.
2. **`wait` без контекста**: сканер готовности засевается незаконченной последней строкой `logBefore(proc, since)`
   (маркер, разрезанный курсором, читается целиком), а «внутри блока» определяется по тому же префиксу
   (`leavesKeyBlockOpen`; `insideKeyBlock` удалён). Хвост редактируется
   `applyLive(tail, …, open || before == null, logBefore(proc, cursor − tail.size))` — это закрывает и многострочные
   шаблоны хоста в `wait`.
3. **Пересокрытие у шейпера**: `finish`, `ended` и MCP шейпят захват, уже отредактированный как живой поток
   (`shapeable`). Если захват больше лимита сканирования или бинарный, он шейпится сырым, и его вид страхует `safeView`.
   `safeView` проверяет то, что реально читал шейпер. Негативный контроль (шейпинг сырого захвата) роняет тест
   «закрытый блок на линии разреза».
4. **Однострочный секрет между опросами**: работающий `poll` (`wholeLines`) отдаёт срез до последнего `\n` и оставляет
   курсор на этой границе. Срез из одной незаконченной строки ждёт перевода строки до `LINE_COMPLETION_SECONDS` = 1 с в
   том же опросе; тихий процесс, строка длиннее `WAIT_LINE_BYTES` или завершение отдают её как есть. На завершении
   отдаётся всё (`ended`, весь лог).
5. **Мелочи**: при пустом `poll.newBytes` префикс лога не читается.

## Хвосты и риски
- Блок, начавшийся более чем за `maxBytes` (256 KiB) до `since` и не закрытый, не распознаётся (то же ограничение,
  что у `insideKeyBlock` в `wait`); `ReadinessScan` в этом случае скрывает — расхождение только для блоков > 256 KiB.
- Терминальные виды теперь редактируются по правилам живого потока. Вывод с маркером `BEGIN … PRIVATE KEY` без `END`
  (например, тест, печатающий маркер) скрывается от маркера до конца вида. Если блок открыт в конце захвата, а его
  `BEGIN` в вид не попал, скрывается весь вид шейпера. Это избыточное скрытие, но на безопасной стороне.
- Однострочный секрет, разрезанный посреди строки между опросами: работающий `poll` теперь держит курсор на `\n`,
  но частичный показ остаётся возможен в трёх случаях: процесс напечатал половину строки и за один дополнительный
  опрос (≤ 1 с) её не закончил; строка длиннее 64 KiB; задан явный `since` посреди строки.
- `Observation.redaction` для среза без blob (`result.log == null`: `poll`/`wait` running) — маска тела, которое
  редактируется повторно (уже скрытые строки там не отмечены). Маска захвата пронумерована по строкам среза, а
  `contentRef` указывает на тело, поэтому простая подстановка дала бы неверное соответствие строк. Правка нетривиальна
  (нужен сдвиг на строки заголовка), поэтому оставлена хвостом. Coverage такие наблюдения не дают (нет путей и
  диапазонов).
- Срез, состоящий из одной незаконченной строки, теперь задерживает `poll` до 1 с.
- Случайный `END` без `BEGIN` в окне скрывает окно до него (как и у `wait`) — избыточное скрытие, безопасная сторона.
