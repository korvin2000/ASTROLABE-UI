## Зачем
Нагрузка владельца — Node. Сейчас у `node --test` разбирается только сводка (счётчики), имена тестов — нет, поэтому
упавший прогон node для строгого регрессионного гейта (D-406) даёт удержание `unknown`, а класс результата падает до
`unverified`. Проверка на Gradle при `gradle` вне PATH остаётся `unavailable`, хотя в репозитории есть wrapper.

## Что сделать
1. **Поштучный результат `node --test`** (репортёры spec и TAP, вложенные наборы): имя теста (с путём набора) и исход
   pass / fail / skip → те же записи поштучных результатов, которые гейт D-406 уже получает от раннеров с поштучным
   выводом. Разбор — один раз на границе вывода инструмента. Неполный или оборванный вывод — честно «неполно», не
   выдумывать исходы. Смешанный вывод (cargo или go вместе с node) — **не трогать** приоритет, записать в хвосты.
2. **`gradle` вне PATH:** если команда проверки — `gradle …` и исполняемого файла нет, а в рабочем каталоге проверки
   есть wrapper (`gradlew` / `gradlew.bat` по ОС) — исполнять через wrapper и записать замену в квитанцию. Нет ни
   того, ни другого — `unavailable` с типизированной причиной, которая доходит до итога (сейчас причина теряется —
   сверить по коду). Запуск — только через существующие `WorkspacePath` и политику эффектов; класс эффекта не менять.
